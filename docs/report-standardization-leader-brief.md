# 报告模块标准化建设方案简版

## 1. 建设目标

报告模块未来要从“按项目开发、按仪器改代码”升级为“平台化、可复用、可扩展”的标准能力。

核心目标只有一句话：

**前端只表达业务需求，平台自动完成模板发现、数据适配、报告生成。**

## 2. 我们准备怎么做

未来标准流程设计如下：

1. 前端先传仪器型号和模板类型。
2. 平台根据规则返回当前可用模板列表。
3. 用户在前端选择模板。
4. 前端再提交 task_id 和 template_id。
5. 平台自动找到对应数据接口，获取数据并生成 PDF。

这意味着：

- 前端不再关心具体模板实现。
- 模板不再直接绑定接口地址。
- 新增仪器时，尽量通过配置和适配器接入，而不是改主流程代码。

## 4. 标准化设计思路

未来平台建议分为四个核心模块：

### 4.1 模板中心

负责管理模板、模板版本、模板适用范围。

作用：让模板成为平台资产，而不是散落在项目里的文件。

### 4.2 适配器中心

负责对接不同仪器、不同 Java 接口、不同数据来源。

作用：新增仪器时，优先新增适配器或配置，不直接改核心流程。

### 4.3 数据标准化层

负责把不同接口返回的数据，统一转换成平台内部标准数据结构。

作用：让模板只面向统一数据模型，不直接适配不同仪器的返回格式。

### 4.4 渲染引擎

负责根据模板和标准数据生成最终报告，并输出 PDF。

作用：未来可以统一支持 Word、HTML 等多种模板方式。

## 5. 数据库建设原则

原则上不建议每个项目单独建立一套报告数据库。

推荐方案是：

1. 建立统一的报告元数据中心库。
2. 模板、规则、版本、适配器配置统一管理。
3. 业务原始数据仍由 Java 服务或业务系统提供。
4. 只有在客户要求独立部署或物理隔离时，才单独建库。

这样做的好处是：

- 模板可以复用。
- 新功能不需要多套数据库重复升级。
- 运维和后期维护成本更低。

## 6. 以后新增一个仪器时怎么做

未来新增仪器，标准动作建议固定为四步：

1. 注册仪器编码。
2. 配置对应数据适配器。
3. 建立标准数据映射。
4. 绑定该仪器可用的模板规则。

这样前端仍然走同一套流程，平台自动返回可选模板并完成报告生成。

## 7. 预期收益

这次标准化建设完成后，预期会带来四个直接收益：

1. 新增仪器更快，开发模式从“改代码”转为“加配置和适配器”。
2. 新增模板更快，模板可以按版本和规则管理。
3. 新增项目更快，不需要重复复制整套逻辑。
4. 后续平台更稳，维护成本和耦合度显著下降。

## 8. 适合向领导汇报的一句话总结

**我们准备把报告模块建设成统一平台：前端先按仪器和模板类型选模板，后端通过模板中心、适配器中心和标准数据模型自动完成报告输出，从而支持未来多仪器、多模板、多项目快速复用。**
